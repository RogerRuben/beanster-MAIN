Beanster Sips V17.7 Acceptance Report
=====================================

Device evidence from V17.6
--------------------------
The on-device self-test reported: 图片没有传完整.
This means the final native grayscale byte[] length did not equal width*height before JNI.
Therefore the failure is before Tesseract recognition, in WebView -> Android image transport.

Root transport difference found
-------------------------------
V17.6 OCR transport:
  prompt('sipsqueak://ocrchunk', base64Chunk)
  -> chunk carried in onJsPrompt defaultValue.

Beanster's established image/backup transport:
  sipsqueak://imagechunk?data=<percent-encoded-base64>
  -> chunk carried in URI query parameter.

V17.7 change
------------
1. OCR now uses the same URI-query transport style as the established image bridge.
2. First transfer uses 3000 raw bytes/chunk.
3. Each Android chunk write returns ByteArrayOutputStream.size().
4. JavaScript compares every ACK with the exact cumulative expected byte count.
5. Any mismatch resets the entire native buffer and retries from byte 0 at 900 raw bytes/chunk.
6. Android still checks final byte[] length == width*height before JNI.
7. Label preprocessing width reduced to 600 px to reduce transfer volume while preserving Chinese text readability.
